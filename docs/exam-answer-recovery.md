# Восстановление неподтверждённых ответов профильного пробника

25.11.2026. Поставка: ветка codex/quiz-answer-recovery; интеграция в main — отдельное действие. Изменения доступны на обычном localhost через подключённую рабочую копию; миграции не требуются.

## Сценарий и поведение

Выбор, отметки и позиция вопросов синхронно сохраняются в localStorage до ожидания автосохранения. Ключ включает подтверждённый через users/me ID аккаунта и UUID попытки. Сначала успешно загружается принадлежащая пользователю серверная попытка; только затем читается и проверяется локальная копия. В ней нет текстов вопросов, ключей, объяснений, оценок или локального источника дедлайна.

После повторного открытия активной попытки восстанавливается неподтверждённый выбор. На странице отдельно указано, что это копия браузера; «Сохранено» означает подтверждение API. При возвращении события online выполняется безопасный повтор сохранения; остаётся существующая кнопка повтора. Ошибка/запрет localStorage видимы явно.

Если PATCH уже отправлялся, локально хранится неизменённое тело и UUID этого запроса. После возвращения повторяется именно он, затем более новые изменения отправляются с подтверждённой revision и новым UUID. Серверная логика повторов не менялась. Новая попытка или результат от такого повтора не создаются.

Если без ожидающего запроса серверная revision изменилась, локальная копия показывается с конфликтом и редактирование/отправка блокируются до явной загрузки серверной версии. Ожидающий запрос разрешается сервером: он либо узнаёт повтор, либо возвращает 409. Запись поверх новой версии не выполняется молча.

Неопределённый исход завершения также сохраняет прежнее тело и UUID и блокирует редактирование после восстановления. Автоматического завершения при восстановлении нет. Завершённая серверная попытка заменяет локальные ответы и очищает копию. После серверного дедлайна поздние локальные ответы не отправляются и не добавляются к результату.

Копия удаляется после подтверждения всех изменений, явной успешной загрузки серверной версии или получения завершённой попытки. Произвольный TTL не вводился. Неудачная загрузка не удаляет копию.

## Проверки

До исправления три новые регрессии падали: потеря множественного выбора/отметки до autosave; потеря более новых правок после потерянного ответа; отсутствие защиты локальной версии при более новой серверной revision. После исправления проходят.

Из корня рабочей копии:

    node --test services/frontend/tests/examRecovery.test.js services/frontend/tests/examSession.test.js services/frontend/tests/examSurface.test.js

Полный frontend-набор из services/frontend:

    npm test

Итог: 189 тестов, 189 passed, без skip/xfail; из них 16 новых проверок восстановления. Три исходные регрессии до исправления падали, после исправления проходят.

Изолированное превью из services/frontend (нужен уже собранный образ saqbol_lms-core_service:latest):

    node tests/runExamPreview.mjs 4187

Адрес: http://127.0.0.1:4187/exams

Docker --network none, read-only исходники, временная SQLite :memory:, искусственный пользователь и 30+20 искусственных вопросов, без .env и рабочей БД. Кнопки сбоя есть только в служебной панели превью. Обрыв сохранений переключается той же кнопкой; потеря ответа сохранения происходит после реальной записи Django.

Проверка реального контроллера и обработчиков API при работающем превью, из корня:

    node services/frontend/tests/exam-preview/recovery.mjs 4187

Проверены сохранение/восстановление, исходный UUID и тело после потерянного ответа, последовательная запись более новых правок, конфликт с более новой серверной версией, завершение по серверному дедлайну без позднего ответа и без лишних попыток/результатов. Это не копия серверного алгоритма и не моки валидации/оценивания.

В браузере проверено повторное открытие той же попытки при заблокированном PATCH с восстановлением ответа и отметки; повтор после восстановления связи и запись в SQLite. Потеря ответа после записи множественного выбора A+C: повторное открытие вернуло выбор; серверная revision осталась 2, одна попытка, без результатов. Проверены desktop и viewport 390×844. Перезагрузка через инструмент остановилась предупреждением beforeunload, поэтому браузерное восстановление подтверждалось повторным открытием той же попытки в новой вкладке, а не заявляется подтверждённым принудительным reload.

Точная команда сборки из services/frontend:

    node --input-type=module -e "import {build} from 'vite'; import react from '@vitejs/plugin-react'; import tailwindcss from '@tailwindcss/vite'; await build({configFile:false,envDir:false,envPrefix:'__EXAM_RECOVERY_CHECK__',plugins:[react(),tailwindcss()],build:{outDir:'dist/exam-recovery-check',emptyOutDir:false}});"

Сборка завершилась с exit code 0. Сборка выполнялась через существующий Vite с envDir:false, чтобы не читать .env; зависимости не менялись. Предупреждения DaisyUI @property и большого JS-bundle остались.

## Границы

Это защита одной профильной попытки в том же браузере и аккаунте. Если сервер полностью недоступен, повторное открытие не позволяет проходить экзамен без проверки статуса: локальная копия сохраняется до успешной загрузки. Очистка хранилища, инкогнито, другой браузер/устройство не покрываются. Одновременная работа нескольких вкладок не считается решённой; серверная revision защищает от устаревшей записи.

Backend, модели, миграции, оценивание, таймер, QuizPage, конструктор, банк и зависимости не изменялись. Рабочая БД не использовалась. Проверки временной SQLite не выдаются за новую проверку PostgreSQL. Известные воспроизведения обработки HTML в общем наборе тестов остаются воспроизведениями, а не исправлениями.
