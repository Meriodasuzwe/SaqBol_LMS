# Импорт одного фиксированного варианта КТ

Команда `import_kt_variant` загружает один комплект 30 + 20 в **существующий** Quiz режима `kt_profile`. Вопросы остаются в Quiz → Question → Choice. Это не общий банк, не переиспользование вопросов между курсами и не случайная сборка пробника.

Команда не создаёт Course, Lesson или Quiz, не меняет их название/описание, не публикует курс, не устанавливает `exam_configuration_key`, не вызывает lifecycle попытки и не меняет grader. В ней нет `--force`, удаления, замены или исправления существующего набора.

## Файлы формата

- [kt-variant.schema.json](kt-variant.schema.json) — JSON Schema 2020-12.
- [kt-variant.example.json](kt-variant.example.json) — **два искусственных вопроса**, `example_only: true`. Это иллюстрация, не официальный банк и не проверенный учебный материал. Полную проверку 30 + 20 этот файл намеренно не проходит; импортировать его нельзя.
- [m094-profile-kk-saqbol-20261112-v1.json](m094-profile-kk-saqbol-20261112-v1.json) — локальный фиксированный вариант M094 на казахском: 30 + 20 вопросов, 290 вариантов, объяснения. Это редакционный комплект SAQBol, не официальный вариант НЦТ.
- [m094-profile-kk-editorial-changes.json](m094-profile-kk-editorial-changes.json) — 12 редакционных решений с исходным и итоговым текстом для проверки.
- Искусственный генератор полного пакета находится исключительно в `tests/fixtures/kt_variant_package.py`. Он помечает результат `example_only: true`; тесты снимают этот признак только внутри изолированной тестовой БД. Он не используется для наполнения localhost.

Вход — JSON UTF-8. Повторяющиеся ключи объектов, неизвестные поля и неверные типы отвергаются. Команда проверяет не только JSON Schema: она также проверяет уникальность ID, принадлежность ключей, источники, порядок секций и совместимость блоков кода с существующим отображением. Сама команда не требует библиотеки JSON Schema.

Корневые обязательные поля: `schema_version` (целое `1`), `package_id`, `example_only` (JSON boolean), `sources`, `questions`. ID — 1–128 ASCII-букв/цифр/точек/дефисов/подчёркиваний; первый символ — буква или цифра. Это локальные ID файла, **не** PK базы. Целевой Quiz задаётся только `--quiz-id`.

`sources`: непустой массив объектов `id`, `title`, необязательный `file_sha256` (64 строчные hex-цифры). ID источников уникальны. SHA исходного документа — сведения о предоставленном источнике; команда не ищет этот документ, не читает его и не подтверждает его содержимое или права на использование.

Каждый элемент `questions` содержит:

| Поле | Правило |
|---|---|
| `id` | Уникальный ID вопроса в пакете |
| `kt_subject` | `first_subject` либо `second_subject` |
| `source` | Объект `id` существующего источника и непустой `location`: страница, номер задания или другое точное место |
| `text` | Непустая строка; исходные пробелы/переносы сохраняются |
| `choices` | Непустой массив `{id, text}`; ID уникальны внутри вопроса; текст непустой и не длиннее 255 символов |
| `correct_choice_ids` | Непустой массив локальных ID вариантов этого вопроса, без повторов |
| `explanation` | Обязательное поле: строка или `null`; пустая строка допустима |

Полный пакет содержит сначала ровно 30 вопросов `first_subject`, затем ровно 20 `second_subject`. В первом предмете у каждого вопроса один правильный вариант, во втором — от одного до трёх. Число **всех** вариантов не фиксируется как 5/6/8: такого ограничения нет в действующей модели/grader. Загрузчик дополнительно вызывает существующий калькулятор для проверки ключей и структуры; нового алгоритма баллов нет.

Отсутствие объяснения (`null`, `""` или только пробельные символы) — предупреждение и счётчик в отчёте. Оно не запрещает черновую загрузку. Неизвестные тема, сложность, ответ или происхождение не угадываются.

## Строки и реальное отображение

Строки сохраняются **без** `strip`, нормализации Unicode, перевода CRLF в LF или обрезания. В JSON перенос записывается как `\n`, табуляция как `\t`. `explanation: null` сохраняется как SQL NULL, не как `""`; различие остаётся значимым при повторе. Нулевой символ и одиночные Unicode-суррогаты отвергаются до записи, поскольку они не представимы в PostgreSQL UTF-8.

Новый `/exams` использует существующий `ExamText` для вопроса, вариантов и объяснения. Обычные переносы/пробелы сохраняются через CSS `pre-wrap`; код выводится в `pre/code` с горизонтальной прокруткой. Это **не полный Markdown**: заголовки, жирный текст, inline-backticks, Markdown-таблицы и ссылки на картинки остаются буквальным текстом. HTML экранируется, а не исполняется.

Поддерживаемый код: отдельная строка из трёх backticks с необязательным языком (`sql`, `python` и т. п.), затем LF либо CRLF, содержимое и отдельная закрывающая строка из трёх backticks. Inline/unclosed fences отвергаются с путём поля: существующий рендерер может терять такое содержимое, и загрузчик его не переписывает. Вложенные fences не поддерживаются. Даже корректный код в варианте ответа должен помещаться в 255 символов; иначе команда возвращает ошибку, а не обрезает текст.

Для задания, зависящего от изображения, настоящей таблицы, схемы или rich text, текущего формата может быть недостаточно. Нельзя удалять этот фрагмент или заменять его выдуманным текстом. Такой материал требует отдельного решения до импорта. Команда проверяет структуру строк, но не может доказать, что человек перенёс всё условие исходного задания. Старый QuizPage использует другой рендерер и не является подтверждением отображения fences в этом сценарии.

## Журнал и контрольные суммы версии 1

Миграция `quizzes/0008_quiz_import_receipt.py` создаёт только `QuizImportReceipt`: уникальную связь с Quiz, глобально уникальный `package_id`, `package_checksum`, `content_checksum`, `manifest`, время создания. Старые вопросы/результаты не изменяются. Журнал не зарегистрирован для редактирования в админке. При явном удалении Quiz он удаляется каскадно; откат миграции при наличии журналов запрещён, чтобы не потерять происхождение молча.

Обе контрольные суммы используют строго определённое представление:

```python
json.dumps(value, ensure_ascii=False, sort_keys=True,
           separators=(',', ':'), allow_nan=False).encode('utf-8')
# SHA-256 этих байтов, 64 строчных hex-символа.
```

`package_checksum` охватывает весь проверенный входной объект: версию, ID, признак примера, источники и вопросы. Пробелы между JSON-токенами, порядок ключей объектов и эквивалентные Unicode escape-последовательности не меняют сумму. Порядок **всех массивов**, включая вопросы, варианты, источники и `correct_choice_ids`, значим. Строки, переносы, пробелы кода, предмет, ключи и объяснения значимы. Никакие строки не нормализуются.

`content_checksum` вычисляется по **свежему чтению ORM после INSERT**, а при повторе — по новому чтению БД. Представление содержит:

- `schema_version: 1`;
- `quiz`: `id`, `lesson_id`, `mode`, `title`, `description`;
- `questions` в порядке PK: `id`, `kt_subject`, `text`, `explanation`, `choices`;
- `choices` в порядке PK: `id`, `text`, `is_correct`.

Статус Course и `exam_configuration_key` намеренно не входят в эту сумму: последующая публикация/привязка не меняет импортированный контент. Поля `id` входят, поэтому удаление и создание похожих записей не принимается за прежний набор. Проверяются также сохранённый manifest и его соответствие ID.

`manifest` содержит версию, `package_id`, `example_only`, исходный массив `sources`, а для каждого вопроса — локальный `id`, созданный `question_id`, `source`, `kt_subject`, список пар `id` → `choice_id`. Полных текстов/правильных ответов как второго банка в нём нет.

## Первая запись, повтор и конфликты

Первый импорт требует: Quiz существует, `mode=kt_profile`, нет вопросов и журнала, `exam_configuration_key=''`, родительский Course имеет **существующий статус** `draft`. Существующий непустой Quiz без журнала автоматически не присваивается импортёру.

При `--apply` команда в `transaction.atomic` блокирует целевой Quiz, читает состояние, проверяет родителей и создаёт вопросы/варианты последовательно в порядке файла. Журнал записывается последним в **той же** транзакции. Любая ошибка откатывает весь пакет, включая журнал. Ограничения уникальности журнала защищают от гонки одного пакета между разными Quiz.

Если журнал уже существует, первая-загрузка больше не проверяется. Совпали ID пакета, его checksum, checksum текущей БД и manifest — возвращается «уже загружено» без INSERT/UPDATE/DELETE. Это работает и после публикации/привязки. Ручное изменение Quiz, вопроса, варианта, объяснения, добавление/удаление вопроса (включая удаление всех), смена пакета или метаданных источника дают конфликт. Никакого молчаливого обновления, очистки привязки или снятия публикации нет.

Гарантия предполагает сохранность самого журнала. Произвольное вмешательство администратора напрямую в БД с удалением/подменой журнала не является поддерживаемым сценарием восстановления. Команда не чинит такое состояние автоматически.

Если после проверки понадобилась правка уже загруженного пакета, это не повтор: подготовить новую версию с новым `package_id` и отдельно согласовать новый пустой Quiz. Старый набор команда не заменяет и не удаляет.

## Команды

Ниже общие команды для окружения с применённой миграцией 0008 и согласованным JSON. На текущем localhost пакет M094 уже загружен в Quiz 118; повторный dry-run возвращает «уже загружено». ID базы не переносимы в другие окружения.

Из `services/core_service` в соответствующем Django-окружении (`123` заменить ID согласованного Quiz):

```powershell
python manage.py import_kt_variant path/to/variant.json --quiz-id 123 --dry-run
python manage.py import_kt_variant path/to/variant.json --quiz-id 123 --apply
```

Если файл позже будет размещён как `/app/imports/variant.json` в обычном контейнере:

```powershell
docker exec saqbol_core_service python manage.py import_kt_variant /app/imports/variant.json --quiz-id 123 --dry-run
docker exec saqbol_core_service python manage.py import_kt_variant /app/imports/variant.json --quiz-id 123 --apply
```

Без режима или с обоими режимами команда завершается с ошибкой без записи. `--dry-run` не создаёт даже журнал; `--apply` повторяет проверки под блокировками. `example_only: true` запрещает запись независимо от правильного размера набора. Структурно корректный example-only пакет можно проверить без записи, с предупреждением.

Отчёт содержит результат (`проверено`/`загружено`/`уже загружено`), Quiz/package ID, число вопросов/вариантов, число вопросов без объяснения и контрольные суммы. Ошибка адресует поле, например `questions[31] (DB-002).correct_choice_ids[1]`. Тексты вопросов и содержимое файла не выводятся в диагностический traceback командой.

Успешная проверка не подтверждает правильность ключей, качество объяснений, тематические квоты НЦТ или разрешение на публичное использование материалов.

## Проверка и последующее подключение

1. Согласовать курс/урок и пустой Quiz. Отдельные сущности не обязательны, если уже есть подходящий **черновой** контейнер; опубликованный курс не переводим в draft автоматически.
2. Подготовить настоящий файл, выполнить dry-run, проверить ошибки/предупреждения и источники.
3. Отдельно разрешить apply в нужной БД, затем проверить в админке все вопросы, варианты, ключи и объяснения. Повтор dry-run должен сообщить «уже загружено».
4. После содержательной проверки перед привязкой повторно проверить, что нет другого Quiz с `mode=kt_profile`, выбранным `exam_configuration_key` и опубликованным родительским курсом. Если есть — остановиться, не заменять его.
5. Отдельным действием установить согласованному Quiz нужный ключ (для этого комплекта `m094_profile_kk_v1`) и опубликовать его курс. Затем убедиться, что подходящий опубликованный источник ровно один и `/exams` считает конфигурацию доступной.
6. Пройти вариант на обычном localhost, проверить сохранение/возврат, баллы и разбор. Это последующая проверка, а не результат тестов импортёра.

**Зависимость каталога:** действующая проверка экзамена требует опубликованный Course. Такой курс появится и в обычном каталоге. Поля `hidden/internal` нет; загрузчик не добавляет его и не обходит проверку. Название и назначение курса нужно согласовать заранее, чтобы не публиковать непонятный служебный контейнер.
