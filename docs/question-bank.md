# Редактор черновиков банка вопросов

Маршрут приложения: `/teacher/question-bank`. Вход — «Банк вопросов» в профиле преподавателя или администратора. Студентам API банка закрыт. Преподаватель читает и меняет только свои вопросы; staff/superuser и роль admin — все. Ключи ответов возвращаются только допущенным авторам.

Модель `quizzes.BankQuestion`, миграция 0010: вопрос хранится без привязки к Course/Lesson/Quiz. Предмет M094 (первый или второй профильный), свободная тема до 255 символов, язык ru/kk, назначение exam/training/both, текст, объяснение, варианты JSON со стабильными UUID и флагами правильности. Подсказки тем взяты из предоставленных спецификаций 2024 года; темы можно вводить вручную. Полей сложности нет.

API `/api/quizzes/bank/` — GET с пагинацией по 20 и фильтрами `search`, `subject`, `usage`, `language`; POST создания. `/api/quizzes/bank/<id>/` — GET/PUT/PATCH. `/api/quizzes/bank/topics/` — подсказки и ID текущего автора для разделения восстановления черновиков. Сервер проверяет 2–8 вариантов, уникальные UUID, непустой текст варианта до 255 символов, строгие boolean ключи, один правильный ответ первого предмета и 1–3 второго. Объяснение необязательно. Переносы и пробелы текста/вариантов сохраняются.

При обновлении нужен `revision`, полученный при чтении. Под блокировкой строки сервер сверяет версию и увеличивает её после записи. Устаревшая версия отклоняется HTTP 400 без перезаписи. При конфликте автор сохраняет текст отдельно и обновляет страницу, чтобы получить свежую версию. Создание при неоднозначной сетевой ошибке пока не имеет отдельного ключа идемпотентности: перед повтором следует проверить список.

Незавершённая форма восстанавливается через sessionStorage отдельно по ID автора; после успешного сохранения очищается. Это локальная защита в пределах браузерной сессии. Серверным сохранением считается только успешный ответ API. Сессия другого автора не подставляет эту форму. При запрете хранилища браузером восстановление не гарантируется.

Все записи этого этапа — черновики. Назначение управляет доступностью выбора в курс: только training/both. Нет автоматического включения в уроки/экзамен, отбора 30+20, публикации, удаления, импорта старых Quiz в банк или исключения уже увиденных вопросов. Действующие Quiz, оценивание, снимки и история не меняются при создании или редактировании записи банка. Связь с курсом описана ниже; комплектование пробника остаётся отдельным этапом.

## Проверка

Backend: `tests/run_training_audit.py` копирует модуль и тест банка в изолированную SQLite без сети. Настоящие обработчики проверяются без моков валидации и сохранения. PostgreSQL runner `tests/run_kt_import_concurrency.ps1` применяет миграции на временной БД и проверяет отсутствие расхождений моделей. Frontend: `npm test`, `npm run build`.

Из `services/frontend`:

```powershell
node tests/runBankPreview.mjs
```

Адрес `http://127.0.0.1:4181/`. Это настоящий компонент редактора с внедрённым API искусственного превью. Данные хранятся в памяти вкладки, рабочая БД и конфигурация приложения не загружаются. Контроль «Показать редактор» позволяет проверить восстановление после размонтирования. Превью не доказывает сохранение в PostgreSQL — это проверяется API-тестами.

Стили ограничены `.qb`: существующие DaisyUI-контролы, синий акцент #2563eb, тема через base-переменные, сетка список/форма на широком экране и одна колонка на телефоне. Используются существующий ExamText для безопасного предпросмотра и иконки lucide. Глобальная тема и DESIGN.md не менялись. Контекст-движок Impeccable недоступен; прочитаны SKILL.md, PRODUCT.md и инструкции new-work/craft-floor. Один review выявил потерю формы при SPA-навигации; исправление восстановлением сессии подтверждено отдельно.


## Выбор банка в конструкторе курса

В QuizGenerator добавлена кнопка «Выбрать из банка». Inline-панель BankQuestionPicker использует существующий защищённый API с `for_training=true`, поиском, точным фильтром темы, предметом и пагинацией. Только вопросы training/both; сервер сохраняет ограничения владельца. Выбранные записи копируются в текущий черновик тестового шага, сохраняя текст, все варианты, ключи, тему, предмет и объяснение. Запись выполняется существующим атомарным `save-generated` по «Сохранить шаг». Исходная запись банка не меняется. Правки банка позднее не обновляют сохранённые копии автоматически.

Тема и предмет проходят загрузку и повторное сохранение конструктора. Текст, объяснение и варианты сохраняют пробелы/переносы; пустые варианты в черновике по-прежнему исключаются с пересчётом индексов правильных ответов. Панель перемонтируется по ID шага, поздние ответы старого запроса игнорируются. Выбранный вопрос нельзя повторно добавить в рамках текущего открытого черновика; после повторного открытия курса связи с ID банка нет, поэтому намеренное повторное копирование возможно. Отдельного списка источников копий и кнопки синхронизации на этом этапе нет.

Мобильные колонки конструктора располагаются вертикально: программа курса доступна в компактной верхней области. Desktop-композиция сохранена.

Из `services/frontend` изолированный настоящий конструктор запускается:

```powershell
node tests/runBuilderPreview.mjs 4182
```

Адрес `http://127.0.0.1:4182/`. Два искусственных вопроса доступны для тренировок, третий с назначением exam в выборе скрыт. Сохранение превью идёт только в память процесса. Настоящее копирование и независимость записей проверяются тестами `test_question_bank.py`; реальная frontend-функция формирования запроса проверяется `builderBank.test.js`. В браузере проверены выбор двух вопросов, сохранение шага, повторное открытие, сохранность ключей, desktop и mobile. Новых миграций для связи не требуется.


## Ручная сборка пробника

Маршрут `/teacher/exam-drafts`, кнопка «Собрать пробник» в банке. Автор выбирает язык ru/kk, вопросы exam/both, ровно 30 первого предмета и 20 второго. Можно менять порядок внутри предмета и удалять выбранное. Сохранение — отдельный immutable `ExamDraft`, миграция 0011. Course/Lesson/Quiz не создаются: это самостоятельный редакционный черновик, не опубликованный источник существующего экзамена. Сложности, автоматические тематические квоты и случайный подбор не добавляются.

API `/api/quizzes/exam-drafts/` GET (свои черновики, у администратора все, по 20), POST создания; `/api/quizzes/exam-drafts/<id>/` GET снимка. PATCH/DELETE/публикации нет. При сохранении сервер получает title/language/request_id и упорядоченные `{id, revision}` банка, перечитывает доступные записи под блокировкой, проверяет назначение, язык, отсутствие повторов, версии, точный состав и ключи существующим grader. Вопросы/варианты/ключи/объяснения/темы и порядок копируются сервером в snapshot. Снимок не зависит от последующего изменения или удаления вопросов банка. Существующие попытки и активный пробник не изменяются.

Повтор того же request_id и тела возвращает тот же комплект, в том числе после изменения банка. Изменённое тело с прежним ID отклоняется. Одновременные повторы одного автора сериализуются блокировкой строки автора и ограничением БД. При неясной сетевой/серверной ошибке UI сохраняет и повторяет замороженный запрос, редактирование блокируется до ответа. Незавершённая сборка и pending-запрос восстанавливаются через sessionStorage по ID автора. Открытие recent и новый комплект заблокированы до завершения восстановления, чтобы медленный ответ не подменил открытый снимок. При закрытии вкладки локальное восстановление может исчезнуть; серверные сохранённые черновики доступны в списке.

Сохранённый снимок открыт только для просмотра. Чтобы составить другой комплект, нужно «Новый комплект»; редактирование сохранённых комплектов или копирование их в новый пока не реализованы. Отдельный следующий этап — проверка и явное подключение выбранного черновика к действующему экзамену. Автопубликации нет.

Из `services/frontend`:

```powershell
node tests/runAssemblyPreview.mjs
```

Адрес `http://127.0.0.1:4183/`. Явно искусственные 50 вопросов и сохранение в памяти вкладки. В браузере проверены выбор через три страницы, состав 30+20, смена порядка первых вопросов, сохранение, повторное открытие, desktop и mobile. API-сохранение и снимки проверяются отдельно в `tests/test_exam_drafts.py`; PostgreSQL runner проверяет настоящий конкурентный повтор создания. Новая таблица не требует удаления или переписывания старых данных.
