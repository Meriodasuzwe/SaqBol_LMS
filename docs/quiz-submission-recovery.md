# Повтор неподтверждённой сдачи обычного QuizPage

25.11.2026. Узкий этап в ветке codex/quiz-answer-recovery вместе с восстановлением профильного пробника и локального выбора до сдачи. Интеграция в main — отдельное действие.

## Исправленный сценарий

Пользователь нажал «Завершить тест», сервер не ответил либо ответ потерялся после записи. После обновления QuizPage прежний код терял submission_id и ответы. Новый запрос мог создать отдельный результат.

Теперь перед POST синхронно сохраняется неизменяемое тело запроса: submission_id, все выбранные ID, включая множественный выбор, и time_spent_seconds. Ключ включает подтверждённый через users/me ID аккаунта, урок и Quiz. Сохраняются исходное начало отсчёта и счётчик предупреждений; они не сбрасываются восстановлением сдачи.

После успешной загрузки теста и проверки аккаунта ожидающая сдача восстанавливается. Пользователь видит объяснение; варианты заблокированы, повтор выполняется явной кнопкой без автоматического POST. Повтор использует исходные UUID, наборы ответов и время. Серверная существующая идемпотентность возвращает прежний Result; backend не менялся.

После подтверждённого результата локальная запись очищается. HTTP 400 означает определённый отказ валидации: копия очищается, ответы можно исправить, новая отправка получает новый UUID. Неоднозначные ошибки и 401/409/429 не превращаются в новую сдачу. Существующее явное действие перезапуска очищает копию и создаёт новое прохождение.

Нечитаемая/повреждённая сохранённая сдача блокирует создание новой, чтобы не потерять её молча. Ошибка записи хранилища видна: в таком случае гарантировать восстановление после закрытия нельзя, но повтор в открытой странице удерживает прежний UUID. Ошибка загрузки теста не удаляет копию.

## Границы

Этот первый этап был ограничен отправленной сдачей. Следующее локальное дополнение — [сохранение выбора до сдачи](quiz-draft-recovery.md); новая серверная попытка не создавалась. Условия заполнения, три предупреждения переключения вкладок, принудительная сдача, порог и правила открытия объяснений не менялись. API и оценивание сохранены. Существующий режим kt_profile в старом QuizPage не подключён к этому локальному хранению; у /exams собственный механизм.

Сохраняется только запрос и технические метаданные, без ключей ответов, объяснений и серверного результата. Автоматического срока удаления не добавляли: до подтверждения, определённого отказа, явного перезапуска или очистки браузера. Смена браузера/устройства и очистка localStorage не покрываются. Одновременная работа нескольких вкладок не объявляется решённой. Невозможность очистить localStorage показывается как ошибка; локальный счётчик неуспешных попыток не превращён в серверную политику в рамках этого исправления.

Рабочую БД, пользователей и их сдачи для проверок не использовали. Модели, миграции, зависимости, курсбилдер и оценивание не изменены. В backend добавлен только изолированный тестовый runner.

## Проверки и команды

Из корня:

    node --test services/frontend/tests/quizSubmissionRecovery.test.js services/frontend/tests/ktQuizIntegration.test.js services/frontend/tests/trainingAudit.test.js

Тест вызывает настоящие fetchData/submitQuiz/handleAnswer/restartQuiz, извлечённые из QuizPage. До исправления главная регрессия падала именно на новом UUID и пустых answers после пересоздания страницы. После исправления проходит. Дополнительно проверены разные аккаунты/уроки/Quiz, исходные множественные ответы и время, сохранение до POST, очистка после ответа/400, ошибки хранилища и принудительная неполная сдача.

Из services/frontend:

    npm test
    node tests/runExamPreview.mjs 4188 --quiz-recovery

Открыть http://127.0.0.1:4188/quiz/lesson/902?quiz_id=904

Стенд использует настоящий QuizPage, JWT, submit Django и ORM в SQLite :memory:. Docker --network none, read-only, временный tmpfs; существующий allowlist копирования приложения не расширяли. Рабочая конфигурация и .env не читаются. Искусственный пароль генерирует существующий runner; он не выводится.

При работающем стенде из корня:

    node services/frontend/tests/quiz-recovery-preview/roundtrip.mjs 4188

Фактически прошли: потерянный ответ после записи → пересоздание страницы → прежние UUID/тело/Result; количества Result, QuizAttemptDetail, QuestionAnswer неизменны при повторе. Отдельно: принудительная неполная сдача, оборванная до записи, восстановилась и сохранилась один раз. Оценивание не подменялось моками в этой проверке.

В браузере на настоящем QuizPage выбраны один/два/один варианта в трёх искусственных вопросах, потерян ответ после реальной записи, выполнен reload, восстановлена замороженная сдача, явный повтор вернул 100% и прежний результат. Состояние SQLite показало сохранённые наборы [2], [4,6], [9]. Это искусственные ID, не пользовательские данные.

Итог полного frontend-набора: 203 теста, 203 passed, без skip/xfail. Из них 14 новых регрессий этого этапа. git diff --check прошёл.

Сборка (из services/frontend, без .env):

    node --input-type=module -e "import {build} from 'vite'; import react from '@vitejs/plugin-react'; import tailwindcss from '@tailwindcss/vite'; await build({configFile:false,envDir:false,envPrefix:'__QUIZ_RECOVERY_CHECK__',plugins:[react(),tailwindcss()],build:{outDir:'dist/quiz-recovery-check',emptyOutDir:false}});"

Exit code 0; прежние предупреждения DaisyUI @property и размера bundle остались. Воспроизведения других HTML-дефектов в общем наборе не считаются исправлениями.
