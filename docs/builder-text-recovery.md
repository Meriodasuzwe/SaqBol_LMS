# Восстановление текстового шага конструктора

Проверки: 24–25.11.2026. Объём: название и rich-text содержимое одного существующего шага типа `text`. Остальные типы шагов, структура курса, настройки, файлы и прохождение тестов не менялись.

## Воспроизведение до изменения

В изолированном настоящем CourseBuilder выбран шаг 905, введён искусственный текст «ИСКУССТВЕННЫЙ ЧЕРНОВИК — этот текст должен пережить обновление.». После «Повторно открыть» и выбора того же шага редактор показал исходный серверный текст, введённое исчезло. Сохранение не нажималось. Это фактическая браузерная проверка исходной реализации.

## Поведение после изменения

`StepEditor` подключает `TextStepRecovery` только для text-шагов. Контроллер `textStepRecovery.js` проверяет автора через `users/me/` и получает свежий шаг через существующий GET. До успешной загрузки не открывает пустой редактор. Локальный ключ: `saqbol.builder.text.<author_id>.<course_id>.<step_id>`.

Название и HTML текстового редактора записываются синхронно при изменении в localStorage. При возврате предлагается восстановить локальный текст или явно оставить серверную версию. Автоматической отправки черновика на сервер нет. При несовпадении исходной серверной версии доступен локальный текст для копирования, а восстановление поверх новой версии заблокировано. Перед явным сохранением выполняется свежий GET и повторное сравнение.

Запись на сервер выполняет прежний `handleSaveStep`; endpoint не менялся, а к запросу текста добавлена исходная версия `expected_version`. Теперь он возвращает подтверждённый объект шага либо null, а конфликт 409 передаёт контроллеру восстановления. Только подтверждённая запись или свежий GET с уже записанным текстом очищают локальную копию. Ошибка не очищает её. Нормализация окружающих пробелов существующим DRF API учитывается; пробелы внутри HTML и кода не удаляются контроллером.

При запрете хранилища показывается предупреждение, серверное сохранение остаётся доступным. Двойное нажатие на сохранение не запускает второй запрос. Во время сохранения текстовый редактор недоступен для ввода. Поздний ответ выгруженного контроллера не подставляет черновик в другой шаг.

## Ограничения

- Защищены только название и текст text-шага. Тестовые вопросы, видео, кодовый тренажёр, файлы, порядок шагов и настройки курса сюда не входят.
- Открытие требует сервера для подтверждения автора и загрузки шага. Это не offline PWA и не резервная копия БД.
- Копия хранится в конкретном браузере до подтверждения записи, явного отказа или очистки браузерных данных. TTL не вводился. Несколько одновременно редактирующих вкладок и перенос между устройствами не гарантируются.
- Начиная с проверки 25.11.2026, обнаруженный промежуток GET/PATCH закрыт серверным сравнением версии под блокировкой строки. Это защита записей через существующий endpoint шага, а не блокировка прямых ORM/SQL изменений или всех возможных редакторов платформы.
- Модели, миграции, зависимости и рабочая БД не менялись. Для атомарной проверки изменены только backend-сериализатор и обработчик шага. Поставка этапа выполняется отдельным PR `codex/builder-text-recovery`.


## Атомарная проверка версии от 25.11.2026

Backend возвращает read-only `edit_version` для text-шага. Это SHA-256 текущих id, типа, названия, содержимого, scenario_data и имени файла, вычисляемый сервером. Это не поле БД и не новая миграция. Перестановка order не меняет текстовую версию. Для других типов шага значение null.

PATCH/PUT, меняющие title/content/step_type/scenario_data/file существующего text-шага, должны передать `expected_version`. Текущий редактор получает её свежим GET и передаёт через тот же реальный handleSaveStep. Под `transaction.atomic` обработчик загружает строку с `select_for_update`, выполняет прежние проверки доступа, сравнивает версию и только затем валидирует и сохраняет поля. Версию нельзя заменить клиентским edit_version.

- Корректная версия: 200 с новым edit_version.
- Устаревшая версия: 409 без перезаписи текста; frontend оставляет локальную копию для сверки и копирования.
- Нет expected_version при изменении текста: 428 без записи. Старым открытым редакторам/клиентам нужно обновиться; прежний незащищённый PATCH текста намеренно не принимается.
- Некорректный тип или формат версии/JSON: 400, без частичной записи.
- PATCH только order и сохранение других типов шагов продолжают действовать по прежнему контракту. Авторизация не ослаблена.

До исправления целевой запуск реального API дал 9 failed / 3 passed. Главная регрессия: второй запрос с устаревшей версией получил 200 вместо 409 и мог затереть первый текст. Дополнительные падения описывали новый обязательный контракт версии, а не отдельные прежние дефекты. После исправления и добавления проверок структуры запроса полный backend-набор дал 813 passed. Старый тест доступности текстового PATCH сохранён и обновлён: он сначала читает версию, затем подтверждает успешный PATCH; запрос без версии проверяется отдельным тестом на 428.

Целевой изолированный запуск из корня (образ уже установлен, сеть запрещена, временная SQLite):

```powershell
docker run --rm --pull never --network none --read-only --tmpfs /tmp:rw,nosuid,nodev,size=256m --mount 'type=bind,source=C:\Users\User\.codex\worktrees\pr-32-merge\SaqBol_LMS\services\core_service,target=/source,readonly' --entrypoint python saqbol_lms-core_service:latest /source/tests/run_training_audit.py --text-step-only
```

Без `--text-step-only` тот же runner выполняет весь backend-набор. Новый test_text_step_version.py явно включён в его список копирования и запуска.

Конкурентная проверка:

```powershell
powershell -NoProfile -File services/core_service/tests/run_kt_import_concurrency.ps1
```

На временном PostgreSQL 15 оба настоящих HTTP/ORM обработчика с одной версией синхронизированы перед SELECT FOR UPDATE. Получены 200 и 409, обе попытки блокировки наблюдались, текст победившей записи сохранился. Проверка не мокает сравнение, валидацию или запись. Runner создаёт отдельную внутреннюю сеть и БД на tmpfs, без рабочих credentials/volumes; затем удаляет только свои ресурсы.

В браузерном превью проверены обычное сохранение, искусственная конкурентная правка между GET и PATCH, сообщение конфликта и сохранность локального текста после настоящей перезагрузки. Превью имитирует транспорт и не доказывает PostgreSQL — для него результат отдельный, выше. Новая кнопка имитации существует только в тестовом превью.

Для использования в обычной установке backend и frontend должны быть обновлены вместе. Миграция для версии шага не нужна. Обычный localhost в этой работе не проверялся; рабочая БД не использовалась и не изменялась. Перед интеграцией 25.11.2026 повторно выполнены 75 целевых frontend-проверок — все прошли. Поставка этого законченного этапа выполняется через отдельный PR `codex/builder-text-recovery`.
