# CNT-03: конструктор → Django → тестовая БД

**Обновление 26 октября 2026:** конструктор теперь сохраняет тест и шаг одним
атомарным запросом. Актуальная приёмка, команды и ограничения описаны в
[ATOMIC_SAVE.md](./ATOMIC_SAVE.md). Результаты ниже от 25 октября — историческая
проверка до этого изменения; два запроса на сохранение больше не являются
ожидаемым поведением текущего конструктора.

В текущей фикстуре также есть пустой quiz-шаг906. Кнопка «Тест: сбой следующего
сохранения» включает однократную ошибку после настоящего `LessonStep.save()`.
Она существует только в стенде и не меняет API приложения. В `/state` поля
`fault_injection.armed/triggered` показывают, был ли сбой выполнен.

Эта проверка дополняет `../builder-preview/README.md`: прежнее превью на 4177
имитирует API; здесь используется настоящий CourseBuilder и настоящий `src/api.js`.
Код приложения не заменяется. Это тестовый стенд, не режим запуска рабочего сайта.

## Запуск

Нужны уже установленные frontend-зависимости, запущенный Docker и существующий
локальный образ `saqbol_lms-core_service:latest`. Runner не устанавливает пакеты и
не скачивает образ. Из корня этой рабочей копии:

```powershell
cd services/frontend
node tests/runBuilderRoundtrip.mjs
```

Открыть <http://127.0.0.1:4178/>. Порт фиксированный; при конфликте runner завершится
с ошибкой, не остановит чужой сервер и не переключится на рабочий API.
`Ctrl+C` останавливает стенд. Новый запуск создаёт исходную фикстуру заново.

## Изоляция и границы проверки

- Docker: `--pull never --network none --read-only`, исходники смонтированы только
  для чтения; `/tmp` — tmpfs. Runner копирует только разрешённые Python-файлы и
  миграции во временную папку, очищает окружение и использует SQLite `:memory:`.
- `.env`, рабочая БД, реальные пользователи и внешние сервисы не используются.
  Создан один искусственный активный teacher — владелец draft-курса, без
  `is_staff` и `is_superuser`. Три SQL-вопроса — техническая фикстура, не материал КТ.
- Вход выполняется реальным `/users/login/`. Дальнейшие запросы содержат JWT.
  Токены остаются на отдельном origin 127.0.0.1:4178 и не выводятся в журнал.
- Vite передаёт `/api/` через JSONL/stdin контейнеру. Django Client служит
  транспортом: выполняются настоящие URL, middleware, JWT authentication,
  permissions, serializers, views и ORM. Ответы API, валидация и сохранение
  не подменены. Это не проверка production HTTP-сервера или PostgreSQL.
- `/__builder_roundtrip__/state` читает настоящую тестовую БД и показывает
  обезличенный журнал запросов без токенов и паролей. Счётчик `write_requests`
  учитывает записи контента, исключая login/refresh.
- Кнопка «Повторно открыть из БД» заново монтирует настоящий конструктор и
  выполняет штатные GET. Это отдельная проверка помимо чтения `/state`.
- Разрешены только необходимые маршруты чтения, сохранение теста и PATCH шагов903/905.
  Создание курсов/шагов, публикация, AI и другие операции в стенде закрыты.

## Что не закрыто этой работой

CNT-03 в согласованной части ключей, объяснений и валидации конструктора
подтверждён сквозной проверкой. Однако:

- POST сохранения теста и PATCH шага остаются двумя отдельными запросами.
  У первого есть собственная транзакция; общей транзакции нет. Сбой второго
  запроса специально не воспроизводился, атомарность пары не заявляется.
- История/целостная попытка, идемпотентность сдачи, аналитика, HTML и оценивание
  не менялись. Пересоздание Question/Choice при редактировании по-прежнему
  относится к отдельной задаче сохранности истории.
- Адаптивность конструктора не исправлялась: ранее обнаруженное обрезание
  редактора на узком экране остаётся. Повторной мобильной приёмки здесь нет.
- Рабочее окружение, PostgreSQL, нагрузка, публикация курса и студентский
  сценарий прохождения в этом стенде не проверялись.

Добавлены только тестовый frontend-runner, файлы превью в этой папке и
`services/core_service/tests/run_builder_roundtrip.py`. Модели, миграции,
зависимости и код приложения не изменены; commit/push на этом шаге не выполнялся.
