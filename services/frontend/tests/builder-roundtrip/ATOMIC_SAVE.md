# Целостное сохранение теста и шага — 26 октября 2026

Закрываем одну проблему: CourseBuilder записывал тест и LessonStep двумя
независимыми запросами. При отказе второго запроса интерфейс сообщал ошибку,
но вопросы уже изменялись. Исправление не касается истории попыток, оценивания,
HTML, дизайна или мобильной компоновки.

## Что изменено

- `services/core_service/quizzes/serializers.py`: необязательные парные
  `step_id`/`step` и ограниченный сериализатор quiz-шага. Поля шага и теста
  валидируются до изменений.
- `services/core_service/quizzes/views.py`: расширенный POST `save-generated/`
  сохраняет Quiz, Question, Choice и LessonStep в одной `transaction.atomic`.
  Шаг блокируется до определения/блокировки связанного теста. Проверяются права
  автора/администратора, принадлежность уроку, тип шага и сохранённая связь.
  Сервер задаёт `scenario_data.quiz_id`, сохраняет прочие metadata и возвращает
  `quiz_id` вместе с сериализованным `step`.
- `services/frontend/src/CourseBuilder/CourseBuilder.jsx`: quiz-ветка отправляет
  один POST с полями шага и принимает результат целиком. Второго PATCH и
  fallback на старую последовательность нет. При отказе нет оптимистического
  обновления сохранённого состояния: введённый черновик остаётся в редакторе.
  Для нетестовых шагов сохранён прежний PATCH.
- `services/core_service/tests/test_builder_atomic_save.py`: 36 новых проверок
  реального API/JWT/ORM. `tests/run_training_audit.py` явно включает этот файл.
- `services/frontend/tests/trainingAudit.test.js`: сохранены 23 регрессии CNT-03,
  ожидание двух запросов заменено на один; добавлены 4 проверки атомарного
  контракта, отказа/повтора, неполного ответа и текстового шага.
- `services/core_service/tests/run_builder_roundtrip.py`, frontend
  `tests/runBuilderRoundtrip.mjs` и `tests/builder-roundtrip/main.jsx`:
  искусственный unlinked quiz-шаг906, наблюдение всех шагов/тестов и однократный
  поздний сбой. Настоящий `LessonStep.save()` сначала выполняется, затем тестовый
  wrapper бросает исключение внутри реальной транзакции. Успешные ответы,
  валидация, авторизация и ORM не подменяются.
- `services/frontend/tests/runBuilderPreview.mjs`: старое превью с имитацией API
  понимает новый формат ответа. Оно не используется как доказательство отката.
- Документация стенда: `README.md` и этот отчёт.

Модели, миграции и зависимости не менялись. Рабочая БД, `.env`, реальные данные
и внешние сервисы не использовались. Прежние посторонние изменения сохранены.

## Фактический браузерный проход

Встроенный Chromium, 1280×720, настоящий CourseBuilder и `api.js`, реальный JWT
обычного teacher-владельца. HTTP из браузера передаётся через локальный JSONL
bridge в Django Client; настоящие middleware, URL, permissions, serializers,
views и SQLite ORM выполняются в контейнере без сети.

1. Изменены название существующего шага, вопрос и два объяснения. Включён поздний
   сбой: **один POST500**, `triggered=1`. БД (включая прежние ID) не изменилась;
   все поля и галочки черновика остались. Показана ошибка, не успех.
2. Без повторного ввода нажата «Сохранить шаг»: **один POST201**. Тест и шаг,
   одиночный/множественный ключ и объяснения сохранены. Новый штатный GET после
   «Повторно открыть из БД» полностью совпал с черновиком.
3. Для нового quiz-шагa906 проверен поздний сбой: **один POST500**, `triggered=2`.
   Лишнего Quiz и вопросов нет; шаг остался без связи; черновик сохранён.
4. Повтор нового сохранения: **один POST201**, всего2 Quiz (прежний и новый),
   новый связан со шагом906. Повторный GET сохранил текст, ключи и объяснения.
5. Название текстового шага905 изменено через прежний **PATCH200** и прочитано
   заново. Содержимое тестов не изменилось.

Итого5 записывающих запросов: 500,201,500,201,200. Контроль включения искусственного
сбоя не является записью контента. В журнале браузера наблюдалось прежнее
предупреждение TipTap о повторных расширениях `link`/`codeBlock` при открытии
текстового редактора; оно не исправлялось в этой задаче.

## Точные границы результата

- Для обновлённого конструктора сохраняется всё либо ничего при исключении
  внутри серверной операции. Потерянный ответ после успешного commit не может
  означать откат; последовательный повтор создания не создаёт лишний Quiz.
  Это не полная идемпотентность содержимого: Question/Choice по-прежнему
  пересоздаются, их ID могут меняться при успешной записи.
- PostgreSQL и конкурирующие сохранения в этом прогоне не проверялись:
  SQLite не подтверждает поведение `select_for_update`. В рабочую БД не заходили.
- Старый API без `step_id`/`step` совместим, но старый двухзапросный клиент
  остаётся неатомарным. При интеграции сначала обновить backend, затем frontend
  (или развернуть вместе). Само развёртывание в этой задаче не выполнялось.
- Обнаружен отдельный прежний дефект: при переходе из заполненного quiz-шага
  в пустой quiz-шаг редактор оставляет предыдущие вопросы. Для проверки создания
  использован явно отредактированный искусственный черновик. Этот дефект не
  исправлялся и создание пустого редактора не объявляется прошедшим.
- История попыток, HTML, мобильная компоновка и иные модули не менялись.
  Commit/push не выполнялись.
